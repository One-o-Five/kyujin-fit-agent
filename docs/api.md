# API設計

ベースパス: `/api`。認証はセッションCookie（[ADR-0003](adr/0003-authentication.md)）。

## エンドポイント一覧

### 認証

| メソッド | パス | 説明 | 認証 |
|---|---|---|---|
| POST | `/auth/signup` | 会員登録（メール、パスワード、招待コード） | 不要 |
| POST | `/auth/login` | ログイン | 不要 |
| POST | `/auth/logout` | ログアウト | 必要 |
| GET | `/me` | ログイン中のユーザー情報と、本日の残り分析回数 | 必要 |

### 職務経歴書

| メソッド | パス | 説明 |
|---|---|---|
| GET | `/resume` | 登録済みの職務経歴書を取得 |
| PUT | `/resume` | テキストで登録・更新、またはアップロード済みファイルのキーを指定 |
| POST | `/resume/upload-url` | S3への直接アップロード用の署名付きURLを発行 |

### 分析

| メソッド | パス | 説明 |
|---|---|---|
| POST | `/analyses` | 求人テキストを受け取り分析を開始。**202 Accepted** |
| GET | `/analyses/{id}` | 分析の状態と結果 |
| GET | `/analyses` | 分析一覧（マッチ度順） |
| GET | `/stats/weaknesses` | 未充足と判定された回数の多い要件 TOP5 |

## 主なふるまい

### `POST /analyses` は非同期

分析には数十秒かかるため、リクエスト時は分析IDと `pending` 状態だけを返す。画面は `GET /analyses/{id}` で完了を確認する。

```json
// 202 Accepted
{ "id": 42, "status": "pending" }
```

処理の流れ:

1. 本日の利用回数を確認し、上限超過なら 429 を返す。
2. 求人テキストのハッシュで `job_posts` を検索し、なければ作成する。
3. 同じ求人・同じ職務経歴書（分析後に更新されていない）の完了済み分析があれば、LLMを呼ばずにその結果を返す（200）。
4. なければ `analyses` を `pending` で作成し、処理キューに登録する（202）。

### 利用量の上限超過

```json
// 429 Too Many Requests
{
  "error": { "code": "DAILY_LIMIT_EXCEEDED", "message": "本日の分析回数の上限に達しました" },
  "resetAt": "2026-11-07T00:00:00+09:00"
}
```

### 職務経歴書のアップロード

ファイルはAPIサーバーを経由せず、ブラウザからS3へ直接アップロードする（サーバー負荷の削減）。

1. `POST /resume/upload-url` で署名付きURLを取得（ファイル種別・サイズを制限）
2. ブラウザから S3 へ PUT
3. `PUT /resume` にS3のキーを渡し、サーバーがテキストを抽出して保存

## エラー形式（共通）

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "...", "details": [] } }
```

| ステータス | 主な用途 |
|---|---|
| 400 | 入力値の検証エラー |
| 401 | 未ログイン |
| 403 | 他ユーザーのリソースへのアクセス |
| 404 | リソースが存在しない |
| 429 | 利用量の上限超過、ログイン試行回数の超過 |
| 503 | サービス全体のLLM利用上限に達し、分析を一時停止中 |
