# 要件定義

## 目的

日本で転職活動をするエンジニアが、日本語の求人票を見て「自分がどの程度マッチしているか、何を補えばよいか、条件面で何を確認すべきか」を5分以内に把握できるようにする。

## 対象と特徴

既存のオープンソース（英語圏のATS対策・履歴書書き換えツールなど）は、英語の求人とキーワード一致の最適化が中心である。本サービスは **日本の求人票と職務経歴書の慣習に特化** し、次の点で差別化する。

* 日本の求人票に特有の項目（固定残業代、試用期間、変更の範囲など）を構造化して示す。
* SIerの工程（要件定義〜試験）など、日本のIT業界の経験の表し方を判定に反映する。
* キーワードの一致ではなく、書類選考・面接で使える根拠とアピール方法を示す。
* 外国籍エンジニアが確認したい条件（日本語要件、ビザ、英語環境）を明示する。

## 想定ユーザー

- 日本で転職を検討しているITエンジニア（外国籍エンジニアを含む）
- 招待コードを持つ人のみ登録可能（初期は知人数名に限定公開）

## ユーザーシナリオ

### メインシナリオ: 求人を1件分析する

1. ログインする。
2. 初回のみ、職務経歴書を登録する（PDF / DOCXのアップロード、またはテキスト貼り付け）。
3. 気になる求人票のテキストを貼り付ける。
4. 求人票が「必須要件 / 歓迎要件 / 給与・労働条件 / 外国籍向け情報」に整理されて表示される。給与に固定残業代が含まれる場合は、その内訳も表示される。
5. 職務経歴書と比較し、要件ごとに ○（充足）△（一部充足）×（未充足）と、その根拠となった職務経歴書の記述が表示される。
6. △・×の要件ごとに、「面接でのアピール方法」または「補強すべき学習内容」が提案される。
7. 結果が保存され、これまで分析した求人をマッチ度順に一覧できる。

### サブシナリオ

- 過去の分析結果を開き直す。
- これまでの分析で多く「×」と判定された要件 TOP5 を確認する。

## 日本の求人票に特化した機能

### 1. 給与・労働条件の構造化

| 項目 | 内容 |
|---|---|
| 想定年収・月給 | 下限・上限を数値で抽出 |
| 固定残業代 | 時間数、金額、固定残業代を除いた基本給、超過分の支払いの有無を抽出 |
| 試用期間 | 有無、期間、期間中の条件の違い |
| 雇用形態・契約期間 | 正社員 / 契約社員など、期間の定めの有無、更新の基準 |
| 変更の範囲 | 業務の変更の範囲、就業場所の変更の範囲 |
| 働き方 | リモート可否、フレックス（コアタイム）、出張の有無 |

**記載の確認**: 固定残業代を含む求人では、時間数と金額、固定残業代を除いた基本給、超過分を追加で支払う旨の明示が求められている（職業安定法の指針、2018年1月〜）。また2024年4月からは、業務と就業場所の「変更の範囲」の明示が求められている。これらの記載が求人票に見当たらない場合は「記載なし（応募前に確認推奨）」と表示する。法的な適否は判断せず、あくまで確認を促す表示とする。

### 2. 日本のIT業界の経験表現への対応

* 職務経歴書の工程（要件定義、基本設計、詳細設計、製造、試験、運用保守）を抽出し、「上流工程の経験」などの要件と対応させて判定する。
* 「〇年以上の経験」は、職務経歴書の期間から算出した年数と比較する。

### 3. 外国籍エンジニア向けの情報

| 項目 | 内容 |
|---|---|
| 日本語要件 | 「ネイティブレベル」「ビジネスレベル」「JLPT N1」などを抽出し、職務経歴書の記載と比較 |
| 英語の使用 | 英語での業務・社内公用語の有無 |
| ビザ | 就労ビザのサポートに関する記載の有無 |

## MVPの範囲

| 機能 | 内容 |
|---|---|
| 会員登録・ログイン | メールアドレス + パスワード、招待コード必須 |
| 職務経歴書の登録 | 1ユーザー1件。テキスト貼り付け、またはPDF / DOCXアップロード |
| 求人分析 | テキスト貼り付け → 要件・条件の構造化 → ○△×判定と根拠 → 改善提案 |
| 日本特化の構造化 | 上記「日本の求人票に特化した機能」の1〜3 |
| 結果の保存・一覧 | マッチ度順の並び替え |
| 弱点の集計 | 未充足の多い要件 TOP5 |
| 利用量制限 | 1ユーザーあたりの1日の分析回数、求人テキストの文字数上限 |

## 今回はやらないこと

| 機能 | 理由 |
|---|---|
| 求人URLからの自動取得 | SSRF対策、求人サイトの利用規約確認が必要なため v2 で検討 |
| 職務経歴書の複数管理・更新時の再分析 | MVPの検証に不要 |
| ソーシャルログイン、決済、チーム機能 | MVPの検証に不要 |
| 英語の求人票への対応 | 日本語の求人票に特化する |
| 労働条件の法的な適否の判断 | 専門的判断のため行わない。記載の有無の表示にとどめる |

## コスト制御（非機能要件）

| 対策 | 内容 |
|---|---|
| ユーザー単位の上限 | 1日あたりの分析回数を制限。超過時は HTTP 429 |
| サービス全体の上限 | 月間のLLM利用額に上限を設け、超過時は分析機能を一時停止。LLM API側の利用上限も設定 |
| モデルの使い分け | 求人の構造化は低コストモデル、判定・提案は上位モデル |
| 結果の再利用 | 同じユーザーが同じ求人・同じ職務経歴書で再分析した場合、LLMを呼ばずに既存結果を返す |
| AWS予算アラート | AWS Budgetsで月額の上限を監視 |

## セキュリティ・プライバシー

- 職務経歴書は個人情報として扱い、他のユーザーからは参照できないようにする。
- 求人の原文や分析結果をユーザー間で共有しない（キャッシュもユーザー単位）。
- 外部から取得したテキスト（求人票）はデータとして扱い、LLMの出力はスキーマで検証する（プロンプトインジェクション対策）。
